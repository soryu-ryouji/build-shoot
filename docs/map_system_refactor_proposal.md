# 战场瓦片化与 JSON 地图数据改造方案

- 状态：已确认并实施，功能与视觉验收通过
- 适用范围：战斗场景地图、建筑放置、范围高亮
- 核心原则：一个战斗场景、一套加载管线、多张 JSON 地图

## 1. 背景与问题

当前战场由整张 `assets/ui/arena.png` 平铺构成，再叠加程序绘制的网格、边框和放置高亮，存在以下问题：

1. 战斗区地面与外围背景来自一张完整插画，中央区域视觉上像独立白板，缺少连续的瓦片地面和过渡。
2. 场地网格为 32px，建筑放置名义上使用 64px 格子，实际为铺满现有矩形被拉伸为约 66 × 69.33px，高亮则按 60/64px 绘制，几套尺寸没有对齐。
3. 地图边界、格子中心、放置合法性和范围计算分散在 `main.gd` 等脚本中，更换地图时需要修改多处代码。
4. 当前绿格主要表示射程或施法范围，没有清楚表达“哪些瓦片可以放置”。

## 2. 改造目标

- 使用 Godot 4 `TileMapLayer` 绘制地面、边界和装饰，不再平铺整张地图插画。
- 所有建筑格统一为 64 × 64px，地图、吸附、占用和高亮使用同一坐标系。
- 地图布局、尺寸和规则全部存储在 JSON 中。
- 只保留一个通用战斗场景，打开场景时根据地图 ID 加载 JSON。
- 新增地图只需新增 JSON，不新增场景、不修改战斗逻辑。
- 绿色高亮明确表示可放置瓦片；非法位置使用红色；射程与施法范围使用独立样式。
- 保持当前建筑、怪物、能源、升级和战斗规则不变。

## 3. 非目标

本次不做以下内容：

- 不做地图选择界面，先使用默认地图 ID。
- 不做可视化地图编辑器，第一版直接编辑 JSON。
- 不做玩家 Mod、在线下载或外部地图包系统。
- 不修改怪物滚动阵列、寻路规则和战斗数值。
- 不引入多层高度、旋转地图或动态地形。
- 不把 PNG、TileSet 等 Godot 美术资源改存为 JSON。

JSON 是唯一的**地图数据**存储管线；PNG 和 TileSet 仍作为被 JSON 引用的美术资源存在。

## 4. 总体结构

```text
scenes/
└── main.tscn                       唯一战斗场景

scripts/
├── arena.gd                        战场容器与兼容接口
├── map_loader.gd                   JSON 加载、瓦片生成、格子查询与占用
├── tile_highlights.gd              放置和范围高亮
├── main.gd                         调用统一地图接口
├── placement_ghost.gd              建筑半透明预览与朝向
├── placed_building.gd              建筑行为，选中时请求范围高亮
└── blocks.gd                       使用统一格子范围判定目标

data/maps/
├── industrial_01.json              第一张工业地图
└── industrial_02.json              后续地图，仅作结构示例

assets/tilesets/
├── industrial.png                  工业瓦片图集
└── industrial.tres                 Godot TileSet 美术资源
```

不创建 `MapData.tres`，不为每张地图创建 `.tscn`，也不维护 JSON 与 Resource 两条地图加载管线。

## 5. 运行时节点结构

`MapLoader` 在战斗场景启动时创建或复用以下节点：

```text
Battlefield
├── GroundLayer        TileMapLayer：地面与外围工业地面
├── EdgeLayer          TileMapLayer：边界、拐角和地面过渡
├── DecorationLayer    TileMapLayer：管线、裂缝等装饰
├── HighlightLayer     Node2D：放置和范围高亮
└── Actors             现有怪物、建筑、炮弹与特效
```

绘制顺序为：

```text
地面 → 边界与装饰 → 高亮 → 怪物和建筑 → 炮弹与特效 → 当前拖拽预览
```

高亮必须位于瓦片上方、单位下方，避免绿色填充遮住怪物和建筑。

## 6. JSON 数据格式

### 6.1 示例

以下用 3 × 2 地图演示格式，正式工业地图初始保持 9 × 10 个建筑格：

```json
{
  "version": 1,
  "id": "industrial_01",
  "name": "工业平台",
  "tileset": "res://assets/tilesets/industrial.tres",
  "size": [3, 2],
  "palette": {
    "floor_a": { "source": 0, "atlas": [0, 0] },
    "floor_b": { "source": 0, "atlas": [1, 0] },
    "floor_c": { "source": 0, "atlas": [2, 0] },
    "pipe": { "source": 0, "atlas": [4, 2] }
  },
  "layers": {
    "ground": [
      ["floor_a", "floor_b", "floor_a"],
      ["floor_a", "floor_a", "floor_c"]
    ],
    "decoration": [
      [null, null, "pipe"],
      [null, null, null]
    ]
  },
  "blocked_cells": [[1, 0]],
  "enemy_spawn_cells": []
}
```

### 6.2 字段说明

| 字段 | 必需 | 说明 |
| --- | --- | --- |
| `version` | 是 | 数据格式版本，当前为 1；未来升级时用于兼容旧地图 |
| `id` | 是 | 地图唯一 ID，同时作为默认文件名 |
| `name` | 是 | 地图显示名称，供后续界面使用 |
| `tileset` | 是 | 本图使用的 Godot TileSet 路径 |
| `size` | 是 | `[宽度, 高度]`，单位为格；第一版为 `[9, 10]` |
| `palette` | 是 | 易读瓦片名称到 TileSet 图集位置的映射 |
| `layers.ground` | 是 | 按行排列的地面瓦片，`null` 表示空格 |
| `layers.decoration` | 否 | 按行排列的装饰瓦片，`null` 表示无装饰 |
| `blocked_cells` | 否 | 额外禁止建造的格子，默认空数组 |
| `enemy_spawn_cells` | 否 | 后续地图出生点配置；当前为空时沿用现有怪物生成逻辑 |

`palette` 中：

- `source`：TileSet 的 source ID。
- `atlas`：图集坐标 `[x, y]`，不是像素坐标。
- 后续如需旋转或翻转，可向后兼容地增加 `alternative` 字段。

### 6.3 坐标与尺寸约定

- 格子坐标使用 `Vector2i`，从 `[0, 0]` 开始。
- JSON 每一行对应 Y，行内每一项对应 X。
- `size` 必须和地面数组的行数、列数一致。
- 瓦片尺寸直接读取 TileSet，统一为 64 × 64px，不在每张 JSON 中重复配置。
- 可放置格必须满足：位于地图内、地面非空、不在 `blocked_cells` 中、当前没有建筑。
- 战斗边界由 `size` 和 TileSet 瓦片尺寸计算，不再使用硬编码的 `PLAY_RECT`。
- 外围边框和工业地面由加载器使用同一 TileSet 绘制，相机根据地图实际尺寸自动适配。

## 7. 地图加载流程

打开 `main.tscn` 后执行：

1. 取得默认地图 ID，例如 `industrial_01`。
2. 读取 `res://data/maps/industrial_01.json`。
3. 解析 JSON 并校验版本、字段类型、地图尺寸、数组长度和瓦片名称。
4. 加载 JSON 指定的 TileSet。
5. 清空并重新填充 Ground、Edge、Decoration 三个 `TileMapLayer`。
6. 建立世界边界、瓦片坐标缓存和可建造格集合。
7. 初始化怪物、建筑、高亮和交互系统。
8. 相机根据地图实际尺寸缩放，继续保证完整地图位于 HUD 与商店之间。

加载失败时报告地图文件、字段和坐标等具体错误，并中止该地图初始化，不静默生成一张不完整地图。

建筑占用属于单局运行状态，不写入 JSON。重开或切换地图时清空占用和旧建筑。

## 8. 统一地图接口

`main.gd`、建筑和高亮不再自行计算格距，统一调用 `MapLoader`：

```gdscript
world_to_cell(world_pos)
cell_to_world(cell)
get_play_rect()
get_all_cells()
get_buildable_cells()
is_inside(cell)
is_buildable(cell)
set_occupied(cell, building)
clear_occupied(cell)
get_occupied_building(cell)
```

坐标职责如下：

- 输入阶段：屏幕坐标 → 世界坐标 → `Vector2i` 瓦片坐标。
- 显示阶段：`Vector2i` 瓦片坐标 → 瓦片中心世界坐标。
- 放置阶段：只根据瓦片状态判断合法性。
- 索敌阶段：目标位置转换为瓦片坐标，与范围格集合比较。

不再通过建筑之间的 62px 距离推测占用，也不再把场地外输入强行夹到最边缘格。

## 9. 高亮设计

### 9.1 可放置高亮

开始拖放建筑时：

- 所有可建造且未占用的瓦片显示低透明度绿色填充与细描边。
- 当前指向的合法格提高填充透明度和描边亮度。
- 当前指向的非法格显示红色描边；非法格不显示绿色。
- 已占用、被阻挡和地图外的格子不标绿。
- 半透明建筑预览、底座和朝向箭头继续显示在最高层。
- 结束或取消拖放后，清空放置高亮。

绿色只表示“可以在这里放置”，不再同时表示攻击范围。

### 9.2 射程与施法范围

- 火力建筑仍按瓦片中心到建筑中心的距离计算圆形离散范围。
- 压缩塔仍按当前朝向计算直线覆盖格。
- 范围高亮统一由 `HighlightLayer` 绘制，预览和实际索敌使用同一组格子。
- 使用低透明度青色填充与描边，和绿色放置格区分。
- 拖放火力建筑时，可同时显示绿色可放置格和当前预览位置的青色射程，但射程样式必须更弱。
- 选中已放置建筑时显示其射程；取消选中后隐藏。

实际实现中，范围格在放置格之后绘制，使用较细的青色内框，确保两种高亮重叠时仍能辨认射程。

## 10. 瓦片美术方案

第一套工业 TileSet 包含：

- 64 × 64px 基础工业地面。
- 少量同色系地面变化，降低重复感。
- 外边、内边和拐角，用于战斗区与外围过渡。
- 裂缝、污渍、管线等独立装饰。
- 与现有建筑一致的象牙白、石墨灰和信号橙配色。

要求：

- 战斗区和外围使用同一套材质与色板。
- 地面瓦片接缝不能出现明显亮线或暗线。
- 装饰与地面分层，装饰不决定放置合法性。
- 保留 `arena.png` 作为参考，但新战场不再引用它。
- 第一版以清晰、统一为准，不增加复杂自动地形系统。

## 12. 实施步骤

1. 建立 JSON 校验、MapLoader 和统一格子坐标接口。
2. 用第一张工业 JSON 替换硬编码战斗矩形，完成放置与索敌迁移。
3. 接入工业 TileSet，绘制地面、边界、外围与装饰。
4. 增加统一 HighlightLayer，改造可放置、射程和施法高亮。
5. 更新已有冒烟、响应式和截图测试。
6. 添加一张仅用于测试的不同尺寸 JSON，包含空格和不可建造格，验证无需修改代码即可加载。

每一步都保持场景可启动，避免一次性改写全部系统后集中排错。

## 13. 测试与验收

### 13.1 功能测试

- 默认 JSON 能正常加载，字段错误和尺寸错误能给出明确日志。
- 世界坐标与瓦片坐标在中心、边缘和地图外转换正确。
- 所有建筑格严格为 64 × 64px，吸附和高亮完全对齐。
- 空格、阻挡格、已占用格不能放置。
- 放置、拆除和建筑被摧毁后，占用状态正确更新。
- 射程高亮和实际索敌范围一致。
- 压缩塔预览范围和实际增益范围一致。
- 切换或重开地图不残留建筑与占用数据。
- 不同尺寸、含阻挡区域的第二张 JSON 无需修改代码即可运行。
- 导出包中包含全部地图 JSON。

### 13.2 视觉测试

- 战斗区与外围不再出现明显背景割裂。
- 瓦片没有明显接缝，重复纹理不过度集中。
- 绿色可放置格在亮地面上仍清晰可见。
- 高亮不遮住怪物、建筑、血条和炮弹。
- 当前合法格、非法格和射程格能够快速区分。
- 现有目标分辨率下地图完整显示，不被 HUD 或商店遮挡。

### 13.3 最终验收标准

- 只有一个通用战斗场景。
- 新增地图只需新增一个 JSON 文件。
- 不再使用整张 `arena.png` 构成战场。
- 地图、吸附、占用和高亮共享同一格子数据。
- 现有核心玩法和测试保持通过。

## 14. 风险与处理

| 风险 | 处理方式 |
| --- | --- |
| 手写 JSON 容易出现行列数量错误 | 加载时严格校验，并报告具体行、列和字段 |
| 工业瓦片可能出现接缝或重复感 | 使用无缝基础块、少量变化和独立装饰，结合截图检查 |
| 地图改为整数格后边界略有变化 | 保持 9 × 10 建筑格，相机按新地图尺寸自动适配 |
| JSON 动态加载可能在导出时遗漏 | 在导出预设中显式包含 `data/maps/*.json` |
| 放置与射程同时显示造成干扰 | 放置使用绿色，射程推荐青色，并降低射程透明度 |

## 15. 审核确认项

默认按以下选择实施：

1. 地图数据只使用 JSON，不增加 MapData Resource。
2. 第一张地图保持 9 × 10 个建筑格，格子统一为 64 × 64px。
3. 第一版直接编辑 JSON，不开发地图编辑器。
4. 绿色专门表示可放置；红色表示非法；射程使用青色。
5. 新增地图不需要新增场景或修改战斗脚本。

以上确认项均已实施。
